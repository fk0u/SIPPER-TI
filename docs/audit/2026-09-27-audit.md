# Audit Teknis SIPPER-TI — 27 September 2026

Audit menyeluruh terhadap kode di branch `main` (commit `d003865`) sebelum melanjutkan Milestone 3.

## Ringkasan

- Aplikasi **masih 100% berjalan di mock data** (Zustand + `localStorage`). Supabase hanya dipakai untuk `signInWithOAuth`.
- Skema database & RLS memiliki beberapa celah kritis (eskalasi role, bypass status approval, bucket publik berisi data medis).
- Tidak ada route guard, sehingga halaman khusus KM/Sipen dapat diakses mahasiswa.
- Baseline kualitas: `npm run lint` menghasilkan **4 error & 37 warning** (klaim roadmap "100% lolos" hanya berlaku untuk `next build`, yang tidak menjalankan ESLint). Belum ada test otomatis maupun CI.

## Temuan (urut prioritas)

### A. Keamanan — Database/RLS (`supabase/migrations/20260921_initial_schema.sql`)
1. **Eskalasi hak akses**: policy `Users can update own profile` tanpa pembatasan kolom → mahasiswa bisa `UPDATE profiles SET role='km'`.
2. **INSERT leave_requests terlalu longgar**: hanya cek `created_by = auth.uid()`; mahasiswa biasa bisa proxy atas nama siapa pun dan langsung insert `status='approved'`, `verified_by` palsu.
3. **UPDATE leave_requests tanpa `WITH CHECK`**, bisa ubah kolom apa pun (student_id, tanggal), dan verifikator bisa menyetujui izinnya sendiri.
4. **Bucket `leave-attachments` public** + policy SELECT untuk semua orang → surat dokter (data medis) bisa diakses siapa saja; INSERT tanpa batas path per user.
5. `lecturer_tokens` tidak punya jalur akses anon → portal dosen mustahil jalan di mode live tanpa RPC/`SECURITY DEFINER` atau server-side service role.
6. `handle_new_user` menurunkan NIM dari local-part email (`rian.pratama`) → bukan NIM; logika domain berlapis membingungkan; tidak ada trigger `updated_at`.

### B. Keamanan — Aplikasi
7. **Tidak ada route guard** (tidak ada `proxy.ts`/middleware). `/admin/tokens` bisa dibuka & dipakai mahasiswa (tidak ada cek role di `LecturerTokenManager`); `/approval` hanya menyembunyikan tombol.
8. `switchRole` / `switchUser` di `src/store/useAuthStore.ts` memungkinkan siapa pun menjadi KM — harus hanya aktif di mode demo.
9. Backdoor password `password123` di `loginWithNIM`; login NIM tidak pernah memanggil Supabase.
10. `api/auth/callback/route.ts` tidak memvalidasi domain email (hanya `hd` di sisi klien); param `next` tidak disanitasi.
11. `GuestLecturerView` tidak mengecek `expires_at`; token digenerate dengan `Math.random()`.
12. Semua mahasiswa melihat semua izin (tab "Semua Izin" + alasan medis orang lain); sipen bisa approve matkul yang bukan tugasnya (`course_sipen` diabaikan).

### C. Bug Fungsional
13. **Link dosen hanya bekerja di browser pembuat** (token disimpan di localStorage).
14. Lampiran berupa `blob:` URL (`URL.createObjectURL`) dipersist → rusak setelah reload.
15. `LeaveForm` **memalsukan lampiran** (`picsum.photos`) jika izin non-sakit tanpa file.
16. `todayStr` pakai `toISOString()` (UTC) → di WITA (UTC+8) sebelum 08:00 tanggal default = kemarin.
17. "Jadwal Kuliah Hari Ini" selalu `courses[0]`, tidak berdasar hari.
18. Default state auth = login sebagai Rian → hydration mismatch SSR vs localStorage; `logout` tidak memanggil `supabase.auth.signOut()`.
19. Kelas `dark` di-hardcode di `<html>` → flash tema saat user memilih light.
20. Validasi 5MB tidak cek MIME; error per-file tertimpa (hanya error terakhir tampil).

### D. Kualitas & Dokumen
21. Tidak ada test, tidak ada CI; `as any` di `src/app/page.tsx:245`; `.env.example` tidak ada.
22. `.agents/context-project.md` menyebut Next 14, Shadcn, Framer Motion, rute `/sipen`, `/rekap/[token]`, bucket `permit-proofs`, `/settings` + ForcePasswordModal — semuanya tidak sesuai kode.
23. `docs/test-cases.md` status "Validated" untuk AUTH-02/03/05, DOC-04 yang belum ada implementasinya.

### E. Lint Baseline (4 error)
- `src/app/page.tsx` — `as any` pada tab filter.
- `src/components/layout/ThemeToggle.tsx` — `setState` sinkron di dalam `useEffect`.
- `src/components/reactbits/StaggeredMenu.tsx` — 2 error React Compiler; komponen ini **tidak dipakai** lagi (lihat Mistake Registry Entry 001).

## Tindak Lanjut

Rencana perbaikan dilakukan bertahap: (1) hardening keamanan & logika bisnis, (2) integrasi Supabase dengan mode demo sebagai fallback, (3) test, CI, dan sinkronisasi dokumentasi.
